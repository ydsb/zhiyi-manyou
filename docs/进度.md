### 已完成的关键修复（迁移与调试中定位）

1. 枚举常量实参不支持前向引用 → 改用 `switch` 在方法体内定义状态流转规则
2. `@TableField(typeHandler=...)` 对 MyBatis **自动结果映射无效** → 统一改为枚举名 VARCHAR 存储
3. `new ObjectMapper()` 绕过 JSR-310 模块导致 `LocalDateTime` 序列化失败 → 改为注入容器实例
4. 返回非 200 时容器转发 `/error`（无错误页）导致响应体丢失 → 统一 HTTP 200 + code
5. Spring Boot 3 迁移：`javax.*` → `jakarta.*`、Security Lambda DSL、`EnableMethodSecurity`、`mybatis-plus-spring-boot3-starter`
6. `zy-common` 不应执行 `spring-boot:repackage` → 从该模块移除插件声明
7. **循环依赖**：`SkillServiceImpl` ⇄ `SkillGraphServiceImpl` → 图谱服务改为直接依赖 `SkillMapper`
8. **Spring Security 6 的 ERROR 分发**：默认对所有 dispatcher 类型生效，会把内部错误转发拦成 401 → `shouldFilterAllDispatcherTypes(false)`
9. **解析算法最长匹配缺陷**：原先用 `indexOf` 只取首次出现，同一标签多次出现时会选错 → 改为「首字符索引 + 最长匹配优先」
10. **意图判定距离缺陷**：原先按规则顺序返回首个命中，单字「会」会抢走更靠后的「需要」→ 改为取离技能词最近的关键词，并给规则分级设最小长度

**设计要点（值得在结项材料里强调）**：

1. **FR-M5-06 是创新点 1 的数据来源**。追溯矩阵里创新点 1 明确挂着 FR-M5-06，
   所以这里没有只做 CRUD，而是产出**客观行为语料**（完成率、按期率、拆解粒度、
   启动速度、停滞时长、个人明细）。它与 M6 互评并列呈现以互相印证，
   这正是"减少凭印象打分与互刷好评空间"的技术落点。
2. **只给原始计数，不给综合评分**。加权口径要与 M6 的评价维度对齐并落库为
   不可篡改记录（FR-M6-03），在此处算分会出现两套口径、无法追溯。
3. **存储介质策略化**（FR-M9-06）。`FileStorage` 接口 + `LocalFileStorage` 实现，
   采购云服务后加 `OssFileStorage` 即可切换，业务代码零改动。
4. **逾期只能靠定时任务**。逾期是时间流逝产生的事实，没有用户动作可触发，
   因此 `CollaborationReminderJob` 每 30 分钟扫描（幂等，不重复骚扰）。

**AC-05 实测结果**（这是结项演示最硬的技术点，已逐项验证）：

| 场景 | 结果 |
|------|------|
| 基线（未篡改） | `intact=True`，0/2 异常 ✅ |
| 篡改维度分 / 评语 / 总分 / 评价人 | **全部检出** ✅ |
| 逐项还原后 | 回到 `intact=True` ✅ |
| 无效校验码 | 返回 3056 ✅ |
| 互刷检测 | 自动命中"进入待互评 0 分钟即评价"并标记 `PENDING` ✅ |

**设计要点（值得在结项材料里强调）**：

1. **总分口径唯一**：权重集中定义在枚举里，总分只由一个计算器产出 ——
   否则能力画像（M7）与信用计算（M8）会出现"同一评价不同分数"且无法追溯。
2. **参与哈希的字段必须可逐字节重现**（踩坑后的修正）：
   `dim_scores` 是 MySQL JSON 列，读写往返会改格式，**不能参与哈希**；
   另存 `dim_canonical` 规范串专用于存证。首版没意识到这点，
   导致**未篡改的记录也被误报为篡改**（基线 2/2 异常）。
3. **如实说明能力边界**：只做哈希固化时，有库权限者可连哈希一起重算。
   因此存证分级（`HASH`/`TIMESTAMP`/`CHAIN`），对外统一表述"可检出篡改"
   而非"物理上不可篡改"，校验接口会把等级与边界说明一并返回给验真方。

**三个关键设计决策**（都有踩坑背景，详见 README §6.13）：

1. **雷达图实时算、快照定时落库**：实时算保证 AC-06「随协作数据变化正确刷新」；
   快照用于画历史曲线（实时算给不出历史值）。两者共用同一个计算器，口径天然一致。
2. **只按"我提供的技能"归类**：教别人什么才证明我会什么。若按"涉及的全部技能"，
   雷达图会虚高失真。
3. **无样本返回 null 而非 0**：0 分会被读成"能力很差"，事实是"没有数据"。

**踩到的两个缺陷（都已修 + 加回归测试）**：

1. **信用值域与等级阈值不自洽**（严重，静默算错）：`adjust()` 把值钳在 0~100，
   而等级表定义「优秀 140~179」。用户 150 分被扣 15 分时被钳成 100 —— **惩罚被吞掉 35 分**；
   补偿 +3 在封顶时完全丢失。根因是"值域上限"与"等级阈值"两处约束没对齐。
   现统一由 `CreditLevel.RANGE_MAX`（=200）表达，`CreditRangeTest` 锁定两个场景。
2. **`credit_level` 存储约定不一致**：DDL 注释说 1~5，`CreditService` 写 `ordinal()`（0~4），
   `AuthService` 写死 1。现已统一收敛到 `CreditLevel.levelCode()`，并让重算无条件校正历史脏数据。

- **恢复演练**：每次版本发布前在测试库执行一次恢复验证

## 六、已知坑与注意事项

1. **PowerShell 脚本必须纯 ASCII**：中文 Windows 的 PowerShell 5.1 按 GBK 解析无 BOM 的 `.ps1`，
   中文注释会导致解析错位，报出 `Unexpected token ')'` 这类莫名其妙的语法错误。
2. **`-Dfile.encoding` 不要放进 `$env:JAVA_TOOL_OPTIONS`**：PowerShell 会吃掉 `-D` 参数里的点号，
   报 `ClassNotFoundException: /encoding=UTF-8`。用参数数组或启动脚本。
3. **PowerShell / curl 无法联网**（schannel 被沙箱限制），需要下载时走 Java 或 Maven。
4. **`.m2` 与 npm 默认缓存目录在沙箱外不可写**：统一指到工作区内。
5. **不要并发跑多个 Maven 进程**：会造成 `FileSystemException: 另一个程序正在使用此文件`。
6. **Vite 在受限沙箱下报 `spawn EPERM`**：其 Windows 路径解析会 `exec` 子进程。
   在你自己的终端里正常，无需处理。
7. **枚举列一律以枚举名 VARCHAR 存储**，新增枚举值只能追加、不得改名。
8. **首次登录会强制进入新手导引**（`firstLogin=true`），这是 FR-M1-03 的设计行为。
9. **用 PowerShell 的 `HttpWebRequest` 测带 body 的接口会假性 401**：一旦调用
   `GetRequestStream()` 就锁定了请求头，之后再 `Headers.Add('Authorization', ...)` 不生效。
   必须先加头再写 body，或直接用 `Invoke-RestMethod -Headers @{...}`。
   本项目排查 `/api/skills/parse` 时在此浪费了不少时间（公开接口不校验头所以不会暴露）。
10. **Element Plus 的 `el-col` 必须显式给 `:span`**：只写 `:xs="8"` 会同时生成
    `el-col-24`（`flex: 0 0 100%`），它优先级更高且更靠后，会把响应式类覆盖掉导致竖排。
    正确写法：`:span="6" :sm="12" :md="6"`。
11. **DTO 的时间字段必须声明为 `LocalDateTime`，不要用 String**：全局 Jackson 只为
    `LocalDateTime` 注册了 `yyyy-MM-dd HH:mm:ss` 序列化器；声明成 String 并手工
    `toString()` 会产出 ISO 的 `2026-09-17T20:36:49`，前端 `new Date()` 解析失败
    （本项目集市页曾显示 "NaN 天前"）。M4 的三个 VO 已全部改正。
13. **MyBatis-Plus 会覆盖数据库默认值**：insert 会把实体全部字段（含 null）拼进 SQL，
    显式 NULL 会覆盖 DDL 里的 `DEFAULT CURRENT_TIMESTAMP`，报 `Column cannot be null`。
    自动时间戳必须在 `MybatisPlusConfig` 的 MetaObjectHandler 里 fill（已为 occurredAt 配置）。
14. **`Map.of()` 的 `get(null)` 会抛 NPE**（不可变 Map 不接受 null 键）。key 可能为 null 时
    用 HashMap/LinkedHashMap，或先过滤 null。文件列表接口踩过。
15. **注解式 `@Select` 不解析 XML 实体**：写 `&lt;&gt;` 会被原样发给 MySQL 报语法错误，直接写 `<>`。
17. **参与哈希的字段必须可逐字节重现**：MySQL **JSON 列**读写往返会改格式（加空格、重排），
    不能纳入哈希，否则未篡改的记录也会被误报。本项目为此另存 `dim_canonical` 规范串。
18. **Lombok 实体里不要写与字段同名的 `is*()` 方法**：字段 `Integer anonymous` 已有
    `getAnonymous()`，再写 `boolean isAnonymous()` 会构成歧义 getter，
    MyBatis 解析属性时抛 `Illegal overloaded getter method with ambiguous type`。
19. **配额校验不要在"接受邀约"里重复做**：邀约阶段已把该交换置为 `NEGOTIATING` 并占用配额，
    接受时再校验会把这条交换自己也算进 `ongoing`，导致"配额满时永远无法接受"。
21. **有值域的字段必须检查与所有阈值定义是否自洽**：M8 出现"信用值钳在 0~100，
    而等级表要求『优秀 140+』"，导致扣 15 分被吞掉 35 分。这类问题**不抛异常、只是算错**，
    功能测试很难发现，必须写专门的边界测试。
22. **同一列在不同代码里可能有不同存储约定**：`credit_level` 的 DDL 注释、服务层写入、
    注册流程三处理解不一致（1~5 / ordinal 0~4 / 写死 1）。收敛到枚举方法（`levelCode()`）比
    在每处写数字更安全。
23. **用 SQL 造测试数据时必须核对枚举常量名**：我写 `auth_type='STUDENT'`，
    而 `AuthType` 枚举只有 `CAS/OAUTH2/LOCAL`，导致登录 500。造数据前先查枚举定义。20. **新增接口记得同步白名单**：`/api/certificates/**` 是匿名验真入口，
    漏加白名单会让"无需登录即可验真"的设计意图失效（返 401）。16. **用 `Invoke-RestMethod` 测业务错误会误判**：项目约定业务错误返回 HTTP 200 + code，
    而它对 HTTP 200 不抛异常，`try/catch` 会走成功分支。必须显式检查响应体的 `code` 字段
    （我因此一度误报"M5 权限校验失效"，实际服务端一直是对的）。12. **图谱游走跳数别超过 2**：稀疏图里 3 跳链条几乎能把任意两个技能连起来，
    会把明显不相关的需求算成"间接互补"。`MAX_GRAPH_DEPTH = 2`，
    且与 `DemandCardAssembler` 实际只加载一跳邻域的能力相匹配。
