# 知驿·漫游 —— 改造摸底与分阶段路线

> 本文记录一次完整的架构摸底结论与后续改造规划。
> 定位：在**不改动核心业务主流程**的前提下，补齐"需求文档已定义、代码尚未实现"的能力。
> 分支约定：改动只在个人分支 `yueyong` 上进行，通过 PR 合并到 `main`，不直接推 `main`。

---

## 一、一句话结论

项目主体功能（M1~M9 + S3 语义引擎）已经完整可用，**当前最值得做的不是"引入新框架"，
而是补上需求文档里已经写明、代码里尚未落地的 4 项能力**（缓存外置、接口限流、消息队列削峰、
MCP 式开放接口）。这些项都有 FR/NFR 编号支撑，属于"需求未闭环"而非"引入新技术"。
本轮已先落地限流、登录失败锁定与 JWT 登出撤销，状态实现保持可替换，后续再接 Redis 支持多实例。

## 四、需求缺口（本次摸底的核心发现）

以下 4 项在 `docs/需求文档.md` 中有明确定义，其中安全相关能力已在本轮先行补齐，
其余中间件与协议能力按阶段推进。

| 需求编号 | 需求原文要点 | 代码现状 | 影响 |
|---|---|---|---|
| **NFR-M-03** | 支持横向扩展：应用无状态化，**Session / 缓存外置** | 缓存与安全状态均支持 LOCAL / REDIS 条件切换；Redis 模式按 TTL 过期 | 默认本地模式仍不共享；多实例需启用 Redis |
| **NFR-S-03** | **接口限流与防刷**：登录失败锁定、发布频控、互评频控 | 已加入登录失败锁定、关键接口固定窗口限流；设置 `ZHIYI_SECURITY_STATE_STORE=redis` 后共享计数、锁定状态与撤销名单 | 验真接口仍可按公网暴露规模补充独立频控 |
| **FR-M9-05** | 行为日志采集：点击流、停留时长、沟通频次**进入消息队列削峰后落盘** | 行为日志尚无 MQ；通知已支持 DB outbox 异步投递、幂等与退避重试 | outbox 解除同步通知写库；后续仍需按部署选型接入 RabbitMQ/Kafka，行为日志另行建模 |
| **FR-M9-07 / FR-M9-08** | 开放能力接口：以标准化协议（**借鉴 MCP 思想**）开放匹配与评价能力 | `/mcp` 已提供 JSON-RPC initialize、tools/list、tools/call，复用现有工具实现 | 后续可接入正式 MCP SDK 与鉴权策略 |

> 注：`docs/需求文档.md` 技术选型表中"消息队列"一栏写作 RabbitMQ / Kafka（择一）。
> 若改用 RocketMQ，需同步更新该表并说明理由（延时消息能力适配"互评超时提醒"这一既有业务）。

## 六、明确**不**引入的技术及原因

这一节同等重要 —— 记录"评估后决定不做"的技术，避免后续重复讨论。

| 技术 | 评估结论 | 原因 |
|---|---|---|
| ShardingSphere 分库分表 | ❌ 不引入 | 当前 27 张表、试运行规模下数据量远未达到分片阈值；分片后跨片聚合（集市卡片按 `demand_id` 批量装配、画像按 `sno` 关联）会显著复杂化，且**回退成本极高** |
| Canal 监听 Binlog | ❌ 不引入 | 写入口高度集中（技能标签、图谱关系的写方法各一处），**写时主动失效缓存**即可满足；Canal 需额外维护 canal-server、binlog 格式与位点管理，收益不成比例 |
| Milvus / pgvector 向量库 | ❌ 不引入 | 向量规模为数百条技能标签，进程内精确检索已满足 P95 要求；引入需 4 个容器与约 2G 内存 |
| Nacos / API 网关 / OpenFeign | ❌ 不引入 | 项目为单体应用，需求未要求微服务化 |
| SSE 流式输出 | ❌ 不引入 | 平台无"模型生成"场景（成长周报为模板化拼装），流式无实际收益 |

## 八、本地环境准备（可复现）

### 1. 数据库

按顺序导入 `sql/` 下 11 个脚本（`01` 起，全部幂等）。**注意**：`01-schema.sql` 不包含
`04` 的 `dim_canonical` 列与 `06`/`07` 的 4 张表，**只跑 01 会埋下运行期报错**。

必须使用 `--default-character-set=utf8mb4`，否则 `08` / `10` 中的中文技能名会乱码。

验收：基础表数量 = 27（另执行通知 outbox 迁移后为 28）；`zy_skill` ≈ 786 行；`zy_skill_ontology` ≈ 592 行；`zy_student` = 7 行；中文无乱码。

### 2. 必填环境变量

`application.yml` 共 13 个 `${...}` 占位符，其中**仅 2 个无默认值、必须提供**：

| 变量 | 说明 |
|---|---|
| `ZHIYI_DB_PASSWORD` | 数据库密码（无默认值） |
| `ZHIYI_JWT_SECRET` | ≥ 32 字节；长度不足时应用**拒绝启动** |

其余 11 个（DB_HOST / PORT / NAME / USER、STORAGE_ROOT、NLP_URL、REDIS_HOST / PORT / PASSWORD / DATABASE、CACHE_TYPE）均有默认值。

### 3. 本地凭据的存放位置

`application-local.yml` 已被 `.gitignore` 排除，是存放本地凭据的约定位置。
启用方式：IDEA 的 VM options 填 `-Dspring.profiles.active=local`。

**不要把凭据写入 `application.yml`** —— 该文件被 git 跟踪，会随分支进入 PR。

### 4. 启动

| 组件 | 命令 |
|---|---|
| 后端 | 运行 `com.nwu.zhiyi.ZhiYiApplication`（唯一启动类，靠组件扫描装配） |
| 前端 | `npm install`（仅首次）→ `npm run dev` |
| NLP（可选） | `python -m pip install fastapi uvicorn` → `python train.py` → `python serve.py` |

### 5. 已知环境差异（脚本硬编码）

仓库内脚本与文档存在原作者机器的绝对路径（`G:\DEV\...`）硬编码，在非该路径环境下需覆盖：

| 位置 | 覆盖方式 |
|---|---|
| `frontend/.npmrc` 的 `cache` | 设 `npm_config_cache` 环境变量 |
| `backend/build-env.ps1` 的 `MAVEN_HOME` | 直接使用 PATH 中的 `mvn` |
| `backend/run-server.ps1` 的 JDK 路径 | 设 `ZY_JAVA_HOME` 或传 `-JdkHome` |
| `scripts/backup.ps1` 的 mysql 路径 | 设 `ZHIYI_MYSQL_HOME` |
| `docs/交接说明.md` 全篇路径 | 替换为本机仓库路径 |
