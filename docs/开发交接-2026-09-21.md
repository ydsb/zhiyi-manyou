## 四、风险与已知边界（诚实记录）

### 1. 前端零自动化测试

Vue 侧**没有任何测试**。每次改动靠手工点页面 + 后端/Python 单测兜着。
本次会话改了 9 个前端文件（含布局、路由、解析交互），
**回归风险靠人工验证覆盖**——这是我每次改完都要跑一遍完整验证的原因。

若后续前端改动变多，建议引入 Vitest + @vue/test-utils，优先覆盖：
路由守卫、请求拦截器、`null` 语义处理（本次出现过一类 `!== null` 判断失守的缺陷）。

### 2. 语义模型的能力边界（不是 bug，不要试图调参修）

| 现象 | 原因 |
|---|---|
| 「今天天气不错我想去打球」误召回"天气分析与预报" | 字符 n-gram 无法区分"技能词共现"与"日常句子偶然词重合"（"天气"两字确实都出现） |
| 「需要有人帮我把网站页面画出来」无结果 | 语义分 0.16 被阈值正确拦下；模型抓不到"画页面"= 界面设计这层意思 |

**处置原则（重要）**：绝对分数只分两档 —— 相关 0.37~0.92、噪声 0.05~0.16，中间几乎无重叠。
**不要为了让某个具体句子能出结果而调低阈值** —— 那会把噪声带进所有输入，
是过拟合单个测试用例。正确做法是扩大知识图谱（用关系补语义）或换模型。

### 3. 几个反复踩的坑（已写进代码注释，这里只列位置）

| 坑 | 记录位置 |
|---|---|
| Lombok 字段与 `isXxx()` 构成歧义 getter，MyBatis 直接抛异常 | `CollabTask.confirmed` 字段注释（含两次踩坑历史） |
| MyBatis-Plus 跳过 null 字段 → "清空"必须落空串 | `AuthService.updateProfile`、`CollabTaskMapper.clearConfirmation` |
| 后端 `non_null` 省略 null 字段 → 前端必须用 `!= null` | `DashboardView`、`GovernanceView` 相关行注释 |
| 阈值只能拦"分数低"，拦不住"分数高但无意义" | `SkillServiceImpl.SEMANTIC_MIN_SCORE` 注释 |

> 然后按本文件「三、下一步」做：先补数据备份脚本，再扩图谱关系。

### 环境要点（省时间的几条）

1. **前端必须用 `npm run preview`，不是 `npm run dev`** ——
   dev 首屏 7.5s（未压缩依赖 22MB），preview 748ms。
   代价：改前端代码后必须重新 `npm run build`，preview 不热更新。
2. **本机 IP 会变**（本次会话见它从 `10.51.101.24` → `10.51.174.205` → `10.51.13.169`）。
   CORS 用的是网段通配所以自动适配，但发给同学的地址要重取 —— 用 `check-lan.ps1`。
3. **Python 测试不是 pytest**，直接 `python nlp-service/tests/test_nlp.py`。
4. **重建后端前必须先停后端**，否则 `mvn package` 的 repackage 会因 jar 被锁而失败。
5. **`.ps1` 必须纯 ASCII**（含注释），中文 Windows 的 PowerShell 5.1 按 GBK 解析会错位。
