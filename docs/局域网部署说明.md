# 局域网访问部署说明

> 让同一局域网内的其他设备（手机、同学电脑、答辩演示机）访问本平台的完整步骤。
> 最后更新：2026-09-17

---

## 一、架构：为什么只需要开一个端口

```
局域网其他设备
      │  只访问这一个地址
      ▼
http://<本机IP>:5173        ← Vite（前端 + API 代理）
      │  代理在本机内部转发
      ▼
http://localhost:8080       ← Spring Boot 后端
      │
      ▼
http://127.0.0.1:8901       ← NLP 算法服务（无需对外）
```

**关键点**：Vite 已配置 `/api` 代理，所以外部设备**只需要访问 5173 一个端口**。
后端与算法服务都不必对外暴露 —— 少开一个端口就少一处风险。

| 服务 | 端口 | 是否需要对外 | 原因 |
|---|---|---|---|
| 前端 Vite | 5173 | **需要** | 用户直接访问它 |
| 后端 API | 8080 | 不必（可选） | 已由 Vite 代理，外部无需直连 |
| NLP 算法服务 | 8901 | **不要** | 仅后端调用，属内部服务 |
| PyPI 镜像代理 | 8899 | **不要** | 仅本机装包用 |

## 二、一键自检：先跑这个

不确定现在能不能用？在项目根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\check-lan.ps1
```

它会用**室友的视角**（走局域网 IP，而不是 `localhost`）把 8 项逐一验一遍：

| 检查项 | 验的是什么 | 常见失败原因 |
|---|---|---|
| 本机 IP | 找到正确的局域网地址 | 没连 WiFi |
| 监听 5173 | `0.0.0.0:5173` 而不是 `127.0.0.1` | `vite.config.ts` 的 `host` 被改回去了 |
| 监听 8080 | 后端进程在跑 | 忘了启动后端 |
| 语义服务 8901 | NLP 引擎可用（**可选**，缺了只降级不报错） | 没启动 `serve.py` |
| 前端首页 | `http://<局域网IP>:5173/` 返回 200 | 防火墙拦了入站 |
| 接口代理 | `/api/health` 经 Vite 代理通到后端 | 后端挂了 |
| 登录接口 | 带**局域网 Origin** 的 POST 能成功 | 见下方「一登录就 403」 |
| 跨域响应 | 后端对局域网 Origin 返回正确的 `Allow-Origin` | CORS 白名单没放行该网段 |

全部通过会直接打印**可以发给室友的地址**；有失败项则打印排查方向，退出码为非 0。

> **为什么自检要走局域网 IP 而不是 `localhost`**：跨域白名单、防火墙、网卡绑定
> 这三个最容易出问题的地方，用 `localhost` 测**全都是通过的**，问题只在外部设备
> 上才暴露。本项目已经因为这个吃过两次亏（GET 正常但 POST 403、本机正常但室友打不开），
> 所以自检脚本刻意从外部视角发起请求。

## 三、三步操作

### 第 1 步：确认前端监听在所有网卡（已配置好）

`frontend/vite.config.ts` 中：

```ts
server: {
  host: '0.0.0.0',   // 原来是 127.0.0.1，只允许本机访问
  port: 5173,
  allowedHosts: true, // 放开 host check，详见第 4 步
  ...
}
```

验证方法（在项目里执行）：

```powershell
netstat -ano | Select-String ":5173.*LISTENING"
```

- 显示 `0.0.0.0:5173` → 局域网可达 ✅
- 显示 `127.0.0.1:5173` → 仅本机，需要改成 `0.0.0.0` ❌

### 第 2 步：放行防火墙（**需要管理员权限**）

Windows 防火墙默认拦截入站连接。**以管理员身份**打开 PowerShell，执行：

```powershell
New-NetFirewallRule -DisplayName "ZhiYi Dev Server (5173)" `
  -Direction Inbound -Protocol TCP -LocalPort 5173 `
  -Action Allow -Profile Private,Domain
```

> 若还想让别人直连后端（一般不需要）：
> ```powershell
> New-NetFirewallRule -DisplayName "ZhiYi Backend (8080)" `
>   -Direction Inbound -Protocol TCP -LocalPort 8080 `
>   -Action Allow -Profile Private,Domain
> ```

**为什么不放行 Public**：`-Profile Private,Domain` 只对家庭/工作网络生效，
在咖啡厅、图书馆等公共网络下不会开洞。这是有意的限制。

删除规则（演示完想关掉）：

```powershell
Remove-NetFirewallRule -DisplayName "ZhiYi Dev Server (5173)"
```

### 第 3 步：查本机 IP 并访问

```powershell
ipconfig | Select-String "IPv4"
```

找到无线/以太网网卡的 IPv4 地址（本项目当前环境是 `10.51.101.24`），
然后在其他设备浏览器打开：

```
http://10.51.101.24:5173
```

## 四、启动顺序（每次重启电脑后）

```powershell
# 1) 后端（必须最先起）
$env:ZHIYI_DB_PASSWORD = '你的数据库密码'
java -jar G:\DEV\zhiyi-manyou-repo\backend\zy-server\target\zy-server.jar

# 2) NLP 算法服务（可选；不起则自动降级为关键词匹配）
$env:PYTHONPATH = 'G:\DEV\python-venv\Lib\site-packages'
python G:\DEV\zhiyi-manyou-repo\nlp-service\serve.py --port 8901

# 3) 前端
cd G:\DEV\zhiyi-manyou-repo\frontend
npm run dev
```

> **NLP 服务没起也能演示**：`SemanticMatchClient` 会自动降级到关键词通道，
> 响应里标注 `channel=keyword`，其他功能不受影响（NFR-R-03）。

## 五、常见问题

### 其他设备打不开，本机却正常

按顺序排查：

| 检查 | 命令 / 方法 | 说明 |
|---|---|---|
| ① 监听地址 | `netstat -ano \| Select-String ":5173"` | 必须是 `0.0.0.0:5173` |
| ② 防火墙 | 见第 2 步 | 最常见原因；漏了这一步外部一律连不上 |
| ③ 同一网段 | 两台设备的 IP 前三段是否一致 | `10.51.101.x` 与 `192.168.1.x` 不在同一局域网 |
| ④ 网络类型 | 设置 → 网络 → 属性 | 若是「公用网络」，而规则只放行了 Private，则会拦截 |
| ⑤ 手机热点隔离 | 部分路由器/热点开启「AP 隔离」 | 设备之间互相不可见，需关闭该选项 |

### 后端 API 报 401 或连不上

局域网访问时前端请求走的是 Vite 代理（`/api` → `localhost:8080`），
**代理在服务器端执行**，所以 `vite.config.ts` 里的代理目标写 `localhost` 是对的，
**不要**改成局域网 IP —— 改了反而会因为绕回本机而变慢或失败。

### 其他设备"能打开页面，但一登录就报 403"

这是本项目实际踩过的坑，现象很有迷惑性：**浏览、检索等 GET 接口都正常，
只有登录 / 发布之类的写操作失败**，后端返回 `403 Invalid CORS request`。

原因：跨域白名单里私有网段最初写成了

```
http://10.[*].[*].[*]:[*]        ← 错误写法，规则静默失效
```

Spring 6 的 `CorsConfiguration.OriginPattern` **只把端口段的 `[*]`
当作"任意端口"**（内部正则 `(.*):\[(\*|\d+(,\d+)*)]`），
主机名段里的 `[*]` 会被 `Pattern.quote` 转义成**字面量**。
所以这条规则永远匹配不上，而启动日志仍会照常打印模式列表 ——
不报错、不告警，只是不生效。

为什么 GET 看起来正常：GET 属于"简单请求"，不触发 OPTIONS 预检；
而带 `Content-Type: application/json` 的 POST 会先发预检，
预检被拒后浏览器直接拦掉，表现为登录 403。

正确写法（主机名段用 `*`）：

```
http://10.*.*.*:[*]       ← 带端口
http://10.*.*.*           ← 省略端口（* 不匹配空串，必须单独列一条）
```

已由 `backend/zy-server/src/test/java/com/nwu/zhiyi/config/CorsOriginTest.java`
（11 个用例）锁定，改错会直接测试失败。需要额外域名时配置
`zhiyi.cors.allowed-origin-patterns` 覆盖默认网段。

> 排查技巧：`vite.config.ts` 里的 `changeOrigin: true` **只改写 `Host`，
> 不改写 `Origin`**，所以后端收到的仍是局域网 Origin，白名单必须放行它。

### 想更正式一点（不跑开发服务器）

开发服务器适合答辩演示，不适合长期运行。若要更稳，可把前端构建产物交给后端托管：

```powershell
cd G:\DEV\zhiyi-manyou-repo\frontend
npm run build          # 产出 dist/
```

然后在后端配置里把 `dist` 目录加为静态资源目录（Spring Boot 的
`spring.web.resources.static-locations`），之后只需访问 8080 一个端口。
好处是省掉 Vite 进程、刷新更快、且与生产形态一致；
代价是每次改前端都要重新 build。

## 六、安全提醒

1. **只在可信网络里开**：`0.0.0.0` 意味着同网段任何设备都能访问，
   规则已限制为 Private/Domain，但公共网络下仍建议关闭服务。
2. **演示账号密码是弱口令**（`123456`）：局域网演示可以接受，
   但**不要**把该环境暴露到公网。
3. **不要放行 8901 / 8899**：前者是内部算法服务，后者是本机装包用的镜像代理，
   都不需要对外，放开只会增加攻击面。
4. **演示完关掉防火墙规则**：见第 2 步的删除命令。
