## 五、技术约定

### 5.1 统一响应体

```json
{ "code": 0, "message": "登录成功", "data": { }, "traceId": "...", "timestamp": "2026-09-17 19:45:16" }
```

**状态码约定（重要）**

| 场景 | HTTP | code |
|---|---|---|
| 成功 | 200 | 0 |
| 参数错误 | **200** | 1xxx |
| 业务错误 | **200** | 3xxx |
| 未登录 / 令牌无效 | 401 | 2001 |
| 权限不足 | 403 | 2002 |
| 系统异常 | 500 | 5xxx |

> 参数类与业务类错误一律返回 **HTTP 200**，真实语义放在 `code`。
> 原因：返回非 200 时容器会转发到 `/error`，而项目未注册错误页
> （`spring.web.resources.add-mappings=false`），响应体会丢失。
> 前端只需判断 `code != 0` 即视为失败。
>
> **已知行为**：访问**未认证**且不存在的 `/api/**` 路径会先被 Spring Security
> 拦截，返回 `401 / 2001`（而非 `5002 接口不存在`）。这是"安全过滤器先于
> DispatcherServlet"的必然结果，属于可接受的取舍，不影响正常调用。

错误码分段：`0` 成功 / `1xxx` 参数 / `2xxx` 认证权限 / `3xxx` 业务 / `4xxx` 外部依赖 / `5xxx` 系统。

### 5.2 枚举存储约定

**所有枚举列一律以枚举名（VARCHAR）存储**，例如
`status = 'PENDING_EVAL'`、`auth_status = 'VERIFIED'`。

- 好处：数据可读、SQL 可直接按状态筛选、不依赖 MyBatis-Plus 的枚举处理内部实现
- 约定：新增枚举值**只能追加**，不得改名（改名等于数据迁移）
- 注意：`@TableField(typeHandler=...)` 对 MyBatis **自动结果映射**无效
  （自动映射走类型注册表，不看实体注解），因此本项目不自定义 TypeHandler

### 5.3 认证方式

```
POST /api/auth/login   →  { accessToken, refreshToken, expiresIn, firstLogin, user }
后续请求                →  Header: Authorization: Bearer <accessToken>
```

- 无状态 JWT（HS256），不使用 Session
- 访问令牌默认 **12 小时**，刷新令牌 **7 天**（`zhiyi.jwt.*` 可配）
- `firstLogin=true` 表示用户尚未建立技能画像，前端据此触发「新手漫游导引」（FR-M1-03）
- 生产环境必须通过环境变量覆盖密钥：`ZHIYI_JWT_SECRET`

### 5.4 互评存证（FR-M6-03）

`EvaluationGrade.seal()` 对
`recordId|fromSno|toSno|dimScores|totalScore|comment|createdAt`
计算 SHA-256 写入 `record_hash`，落库后禁止 UPDATE。
`verifyIntegrity()` 可随时复核是否被篡改。

### 6.3 文本解析示例

```jsonc
// POST /api/skills/parse
{ "text": "我需要会做动态交互效果的同学，帮我把作品集页面做得活一点",
  "limit": 8, "withGraph": true }
```

```jsonc
// 响应（节选）
{
  "code": 0,
  "data": {
    "text": "我需要会做动态交互效果的同学，帮我把作品集页面做得活一点",
    "subject": "我",
    "matched": [
      { "skillId": 2, "name": "JS 动画与交互实现", "intent": "SKILLED",
        "score": 1.0000, "matchType": "ALIAS",
        "reason": "同义词「动态交互效果」映射到「JS 动画与交互实现」，意图：擅长（依据「会做」）" }
    ],
    "triples": [ { "subject": "我", "action": "擅长", "object": "JS 动画与交互实现" } ],
    "engine": "RULE_LEXICON",
    "degraded": true,
    "hint": "已返回语义命中标签，图谱关联标签由接口层补充"
  }
}
```

**解析引擎说明**（详见 `SkillTextParser` 类注释）：

1. 文本规范化：全角转半角、统一小写、压缩空白
2. 词典匹配：按**首字符索引 + 最长匹配优先**，长词优先（避免「数据」抢走「数据爬取」）
3. 意图判定：在命中位置前 12 字窗口内，取**离技能词最近**的关键词，区分 擅长/想学/急需
4. 打分排序：匹配方式权重 + 释义加成 + 热度加成，上限 1.0
5. 图谱补全：通过「互补协作」边带出字面未命中的跨学科标签，分数打 0.85 折扣

`engine=RULE_LEXICON`、`degraded=true` 表示当前走的是规则降级通道（满足 NFR-R-03）；
S3 阶段接入 Embedding 模型后，接口契约不变，仅这两个字段与内部实现变化。

### 6.6 匹配度算法（FR-M4-03）

集市排序默认按 `MATCH`，计算的是**双向匹配**而非单向关键词命中：

| 因子 | 权重 | 含义 |
|---|---|---|
| 技能供需匹配 | 0.40 | 我擅长的技能 vs 他急需的技能（图距离衰减：精确 1.0 / 同二级学科 0.75 / 同义 0.85 / 先决 0.70 / 互补 0.50 / 两跳 0.35） |
| 技能置换平衡 | 0.25 | 他提供的技能 vs 我急需的技能（缺失时权重归还上一项，不压低总分） |
| 学科相关度 | 0.15 | 同门类 0.7；跨门类 1.0（跨学科置换是平台价值场景） |
| 时效性 | 0.10 | 6 小时内 1.0，14 天以上 0.2 |
| 活跃度 | 0.10 | 邀约数与浏览数（弱信号，防止零互动卡片沉底） |

≥ **0.75** 判为高匹配，前端高亮置顶。各因子得分与自然语言依据都会返回，
用于「可解释推荐」（FR-M3-03）。

### 6.7 状态机与配额

交换状态流转（非法流转返回 `3007`）：

```
PUBLISHED ──▶ NEGOTIATING ──▶ IN_PROGRESS ──▶ PENDING_EVAL ──▶ COMPLETED
     │              │              │                │
     └──────────────┴──────────────┴────────────────┴──▶ CANCELLED
                                   │
                                   └──▶ DISPUTED ──▶ COMPLETED / CANCELLED
```

- **占用并发配额**的是 `NEGOTIATING` 与 `IN_PROGRESS`：上限取用户 `exchange_quota`
  （默认 **5**，见 FR-M4-09），超限返回 `3008`
- 接受一条邀约后，**同一卡片上的其他待响应邀约自动拒绝**（一张卡片对应一次交换）
- 取消交换时，来源卡片会回到 `OPEN` 重新招募
- 单用户待响应邀约上限 10 条（防刷单，FR-M4-07）

### 6.9 过程性指标（FR-M5-06，创新点 1 的数据来源）

`GET /api/workspaces/{recordId}/process-summary` 输出**客观行为语料**，与 M6 双向互评
并列呈现以互相印证。它<b>只给原始计数与时长，不给综合评分</b> —— 加权口径应与 M6 的
评价维度对齐并落库为不可篡改记录（FR-M6-03），在此处算分会导致两套口径、无法追溯。

| 维度 | 指标 |
|---|---|
| 任务 | 总数 / 完成 / 进行中 / 待开始 / 逾期数、完成率、**按期率**（仅统计有截止时间的已完成任务）、**拆解粒度**（任务数÷参与人数） |

### 6.10 文件存储（FR-M5-03 / FR-M9-06）

### 6.11 打卡提醒定时任务

`CollaborationReminderJob` 每 30 分钟扫描一次未完成且有截止时间的任务：

- **临近截止**（24 小时内）→ 提醒负责人（同一任务幂等，不会重复轰炸）
- **已逾期** → 写一条 `TASK_OVERDUE` 协作事件（只写一次）并提醒双方，
  该事件是 M6 按期率举证的依据

> 因此用定时任务而非实时判断（需 `@EnableScheduling`，已在启动类开启）。

#### 6.12.1 评价维度与总分口径

| 维度 key | 中文名 | 权重 | 评分指引 |
|---|---|---|---|
| `task_completion` | 任务完成度 | 0.25 | 是否按约定完成任务拆解，有无烂尾 |
| `delivery_quality` | 交付质量 | 0.25 | 成果是否可用、是否需要返工 |
| `communication` | 沟通效率 | 0.25 | 响应速度、信息清晰度、配合度 |
| `cross_discipline` | 跨专业协作能力 | 0.25 | 能否理解对方专业语境、把本专业知识讲清楚 |

总分 = Σ(维度分 × 权重)，**口径唯一定义在 `EvaluationDimension` 枚举里**，
由 `DimensionScoreCalculator` 计算。能力画像（M7）与信用计算（M8）都引用同一个
`totalScore` —— 若各处自行加权，会出现"同一份评价在不同页面分数不同"且无法追溯。

#### 6.12.2 存证机制与**如实的能力边界**

两级手段：

1. **哈希固化**（`record_hash`）—— 对评价实质内容计算 SHA-256，字段级改动可被检出；
2. **外部锚定**（`chain_proof` + `evidence_level`）—— 可信时间戳 / 联盟链，S3 阶段接入。

> ⚠️ **已知边界，结项材料中不应夸大**：只有哈希固化时，能改库且有权限的人
> 可以连 `record_hash` 一起重算，使记录重新自洽。要真正抗篡改必须依赖二级锚定
> 或数据库权限隔离。因此对外统一表述为「**可检出篡改**」，而非「物理上不可篡改」。
> 校验接口会把存证等级与这段说明一并返回给验真方。

#### 6.12.3 参与哈希的字段必须是"可逐字节重现"的（重要设计约束）

这一条是**踩过坑之后的修正**，务必遵守：

- `dim_scores` 是 **MySQL JSON 列**，JSON 属于"规范化存储" —— 写入的紧凑串与读回的
  表示可能不同（会加空格、按内部顺序重排），**无法逐字节重现**；
- 首版把它的原始字符串直接纳入哈希，结果连**未被篡改的记录也被误报为"已改动"**
  （基线 `intact=False`，2/2 异常）；
- 修正方案：另存 `dim_canonical` 列，内容是**只由数值决定**的确定性字符串
  （固定 key 顺序、固定一位小数、固定分隔符），用它参与哈希。

参与哈希的字段及其可重现性保证：

| 字段 | 保证 |
|---|---|
| `dim_canonical` | 只由数值决定，与存储格式无关 |
| `total_score` | 统一 `setScale(2, HALF_UP)` |
| `comment` | 封存时已 `trim()` |
| `sealed_at` | 一律截断到秒（与哈希原文格式、MySQL DATETIME 精度一致） |

`sealed_at` 是**独立于 `created_at`** 的时间锚点：后者由 MyBatis 自动填充在 insert 时生成，
与 seal 时刻可能有微秒差异，用它做锚点会导致校验必然失败。

#### 6.12.4 其他关键行为

- **防报复性评价（FR-M6-05）**：双方都提交前，对方的 `dimScores/totalScore/comment`
  **在服务端置为 null** 后返回 —— 不是前端隐藏，绕过前端也拿不到。
- **自动流转**：双方互评齐备后，交换自动从「待互评」推进到「已完成」，
  为 M7 能力画像与 M8 信用计算提供明确触发点。
- **低分强制说明**：总分 < 60 时必须填写 ≥ 15 字说明（对双方都有价值，也是申诉依据）。
- **互刷检测（FR-M6-07）**：四个模式 —— 重复交换、异常时间间隔、高分低信息量、闭环互评；
  命中只标记为 `PENDING` 待人工复核，**不拦截**（同学院同学反复互助是正常且值得鼓励的，
  直接拒评会误伤）。
- **修正以追加实现（FR-M6-03）**：评价本体禁止 UPDATE，争议裁决改分时追加
  `zy_evaluation_amendment` 记录（保留原因、前后分值、操作人），可追溯。

### 6.13 数字档案与能力画像（模块 M7）

| 方法 | 路径 | 说明 |

| GET | `/api/profile/report` | **《跨学科协作能力鉴定报告》**（含 M6 校验码） |
| GET | `/api/profile/weekly-reports?limit=12` | 成长周报列表 |

#### 6.13.1 雷达图口径（可解释性是硬要求）

| 维度 | 数据来源 |
|---|---|
| 工程逻辑 / 数据分析 / 艺术审美 / 人文表达 | 按**我提供出去**的技能的**学科门类**归类（工学→工程逻辑、理学→数据分析、艺术学→艺术审美、文学类→人文表达），以互评总分为质量、协作时长为权重 |
| 沟通协作 | 直接取 M6 互评的 `communication` 维度分 |

映射关系定义在 `AbilityDimension` 枚举里（**口径唯一来源**）。每个维度都返回
`evidence` 字段说明分数出处，例如：

> 「工程逻辑」88.75 分，由以下技能按累计时长加权得出：「ECharts 数据可视化」（工学）换过 2 次、共 6 小时，平均 88.75 分

**四条刻意的设计选择**（都有踩坑背景）：

1. **只按"我提供的技能"归类**：一次交换里我提供 Vue、学到数学建模，能证明的是我的**工程**能力，不是数学能力。若按"涉及的全部技能"归类，雷达图会虚高失真。
2. **先按技能聚合，再按维度加权**：同一技能换过 3 次，若逐次平均就与"另一个只换过 1 次的技能"等权，维度分被重复计数扭曲。
3. **无样本返回 null，不返回 0**：0 分会被读成"能力很差"，事实是"没有数据"。前端据此画虚线并标注"暂无数据"。
4. **无互评的交换照常计入时长，但不出质量分**：互评是双向的，"我提供技能"与"我收到评价"并不总是同时成立。早期实现把这类交换**直接丢弃**，导致已完成的真实协作在画像上毫无体现 —— 这是错的，协作事实已经发生。现在会如实标注"换过 1 次、共 6.5 小时，但尚未收到互评，暂不计分"。

#### 6.13.2 为什么雷达图实时算、而快照定时落库

- 主页雷达图 = **实时计算** → 保证 AC-06「雷达图随协作数据变化正确刷新」；
- 快照 = **定时落库**（每日刷新当月）→ 成长轨迹要画历史曲线，实时计算给不出历史值；
- 两者共用 `ProfileCalculator`，**口径天然一致**，不会出现"雷达图与轨迹对不上"。

#### 6.13.3 勋章与报告

- **勋章求值**：解析 `zy_badge.condition_expr`（支持 `completed_exchange` /
  `distinct_college` / `skill_learners` / `avg_score` / `credit_score` 与 `>=`、`>`、`AND`）。
  读取画像时**按需评估一次**（幂等），不是只靠定时任务 —— 否则用户完成交换后勋章状态不刷新，AC-06 会不通过。
- **未解锁勋章也返回**并带进度（如 `skill_learners >= 5（当前 2 / 目标 5）`）：只显示已获得的勋章会失去引导作用。
- **报告导出**：服务端返回结构化数据，前端排版为可打印 HTML，用浏览器「打印 → 另存为 PDF」。
  <br>**为什么不后端生成 PDF**：服务端生成需引入中文字体（体积大、开源授权需逐一确认），而浏览器打印天然支持中文与 A4 分页，零依赖且样式可控。
- **报告带 M6 校验码**，任何第三方可访问 `/api/certificates/{校验码}` 匿名验真。
  报告同时如实标注存证等级与能力边界，不宣称"物理上不可篡改"。

## 八、常见问题

**Q：`ClassNotFoundException: /encoding=UTF-8`**
PowerShell 破坏了 `-Dfile.encoding=UTF-8`。改用 `run-server.ps1`，或用参数数组方式调用 java。

**Q：登录返回 `code=3001 学号或密码错误`，但密码确实是 123456**
数据库里的 BCrypt 哈希与当前 `spring-security-crypto` 版本不匹配。重新生成并更新：
```powershell
$hash = '$2a$10$MJyq4Y7DyH8hD.wwsFOWWux65d7UEhHYKBeEfnI.b/KlHzYD.2jhO'   # 123456
"UPDATE zy_student SET password='$hash';" | & mysql -u root -p zhiyi_manyou
```

**Q：响应中文乱码**
用 PowerShell 5.1 的 `Invoke-RestMethod` 会按 Latin-1 解码。改用
`[System.Text.Encoding]::UTF8.GetString($resp.RawContentStream.ToArray())`，
或使用 7.x 的 `Invoke-RestMethod`（默认 UTF-8）。服务端本身编码正确。

**Q：哈希校验把"没被篡改的记录"报成篡改**
先检查**参与哈希的字段是否可逐字节重现**。典型陷阱：把 MySQL **JSON 列**的原始
字符串纳入哈希 —— JSON 属规范化存储，写入的紧凑串与读回表示可能不同（加空格、重排顺序），
按实体重建原文永远匹配不上。本项目为 `zy_evaluation_grade` 另存了
`dim_canonical`（只由数值决定的确定性字符串）专用于哈希，详见 §6.12.3。

**Q：`Illegal overloaded getter method with ambiguous type`**
Lombok 已为字段 `Integer anonymous` 生成 `getAnonymous()`，同一实体里再手写
`public boolean isAnonymous()` 会构成歧义 getter，MyBatis 解析属性时直接抛
ReflectionException。便捷方法要起不冲突的名字（本项目改为 `anonymousSubmission()`）。

**Q：`Column ''xxx'' cannot be null`，但表里明明有 `DEFAULT CURRENT_TIMESTAMP`**
MyBatis-Plus 的 insert 会把实体的**全部字段（含 null）**都拼进 SQL，显式传 NULL 会
**覆盖**数据库默认值。凡是"必须自动产生的时间戳"都要在 `MybatisPlusConfig` 的
MetaObjectHandler 里 fill（已为 `createdAt` / `updatedAt` / `occurredAt` 配置）。
本项目在 `zy_collab_event.occurred_at` 上踩过。

**Q：`Map.of()` 报 NullPointerException**
`Map.of()` 返回 Java 不可变 Map，其 `get(null)` 会**抛 NPE** 而不是返回 null。
当 key 可能为 null（如 `taskId` 未传）时，必须用 `HashMap`/`LinkedHashMap`，
或先过滤掉 null 再查。本项目在文件列表接口上踩过。

**Q：注解式 `@Select` 里写 `&lt;&gt;` 报 SQL 语法错误**
注解式 SQL 是**纯字符串，不经过 XML 解析**，XML 实体不会被还原。
直接用 `<>` / `!=` 即可。本项目在 `CollabMessageMapper` 上踩过。

**Q：用 `Invoke-RestMethod` 测试业务错误时判断出错**
本项目约定业务错误返回 **HTTP 200 + code**，而 `Invoke-RestMethod` 对 HTTP 200
**不抛异常**，因此 `try/catch` 会走成功分支，容易把"被拒绝"误判为"成功"。
测试脚本要显式检查响应体的 `code` 字段（`smoke-test.ps1` 的 `Invoke-Probe` 就是这样做）。

**Q：用 PowerShell 测带 body 的接口一律返回 401，但接口明明是通的**
大概率是测试脚本的坑，不是服务端问题。`.NET HttpWebRequest` 一旦调用
`GetRequestStream()` 开始写请求体，就**锁定了请求头**，之后再加 `Authorization`
不会生效：

```powershell
# ❌ 错：先写 body 再加头 → 服务端收不到令牌 → 401
$s = $req.GetRequestStream(); $s.Write(...); $s.Close()
$req.Headers.Add('Authorization', "Bearer $token")

# ✅ 对：先加头，再写 body
$req.Headers.Add('Authorization', "Bearer $token")
$s = $req.GetRequestStream(); $s.Write(...); $s.Close()
```

推荐直接用 `Invoke-RestMethod -Headers @{ Authorization = "Bearer $token" }`。
本项目在排查 `/api/skills/parse` 时踩过此坑，一度误判为服务端问题（公开接口
因为不校验请求头所以不会暴露该问题）。

**Q：`No enum constant ...AuthStatus.2`**
枚举列存的是序号而实体是枚举名。本项目的约定是**枚举名存储**，
请确认表结构为 `VARCHAR` 且值为 `VERIFIED` 等名称。

**Q：构建报 `.m2` 写入被拒绝**
使用 `-Dmaven.repo.local=G:\DEV\.m2repo` 指定工作区内的仓库。
